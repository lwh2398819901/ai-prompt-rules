# 文档对齐代码

## 核心原则

文档对齐代码时，代码是唯一事实依据。任务是修正文档，而不是改变实现。

## 适用场景

- 用户要求让文档匹配代码、文档对齐代码，或按实现核对文档。
- 设计文档、API 文档或业务流程文档与代码不一致。
- 用户询问文档中的行为是否已经真实落地。

不要用于编写尚未确认的设计文档或提出未来行为。

## 流程

1. 阅读相关文档。
2. 检查实现该行为的代码路径。
3. 分类每个不一致：
   - 文档与实现不同：按代码修正文档。
   - 代码已实现但文档缺失：补充缺失行为。
   - 文档写了但代码未实现：标注「未落地」或删除。
4. 尽量保留现有文档结构。
5. 提供差异清单：原内容 -> 修正后 -> 原因。

## 应包含内容

- 从代码确认的真实行为。
- 重要的临时实现选择。
- 仅在有代码依据时补充潜在优化说明。

## 硬边界

- 不修改项目代码。
- 不凭空补业务逻辑。
- 当代码与文档冲突时，不用文档反推真实行为。
- 不保留已确认过时的内容，除非明确标注。

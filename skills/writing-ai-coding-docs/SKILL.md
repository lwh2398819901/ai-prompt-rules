# AI 编程文档书写

## 核心原则

AI 编程文档应提供精准上下文，而不是完整知识库。每一行都应该帮助智能体在具体任务中少猜一点。

## 适用场景

- 用户要求编写、重构或改进面向 AI 的工程文档。
- 某个模块需要为后续智能体提供简洁实现上下文。
- 文档需要指导编码工作，但不应嵌入完整源码。

不要用于 API 参考堆砌、未确认 PRD 或普通文字润色。

## 文档原则

- 信息密度优先：每一行都必须值得读。
- 模块化：一个文档只覆盖一个模块、页面或功能。
- 单一职责：避免混入无关流程。
- 精准相关：只包含高概率任务需要的上下文。
- 优先使用表格、列表、伪代码和流程图，而不是长段落。
- 任务关键上下文放在本地；共享上下文用链接引用，不大段复制。

## 前端文档

| 写什么 | 不写什么 |
| ------ | -------- |
| 布局和视觉结构 | 完整 Vue / React 组件代码 |
| 用户交互流程 | 状态管理实现细节 |
| 表单字段 | Axios 或请求封装细节 |
| 调用哪些 API | 路由守卫实现 |
| 枚举值映射 | |
| 按钮权限规则 | |

## 后端文档

| 写什么 | 不写什么 |
| ------ | -------- |
| 业务流程 | 完整函数体或类定义 |
| 关键设计决策 | ORM 查询细节 |
| 数据结构 | HTTP 客户端封装内部实现 |
| 伪代码逻辑 | 大量真实代码块 |
| API 调用顺序 | |
| 错误码映射 | |

## 联动检查

文档变更时，检查是否影响数据设计、API 合同、业务流程、实现指南、权限或约束。只有当前任务包含对应范围时，才更新相关文档。

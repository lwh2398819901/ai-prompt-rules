# 行为保持型简化

## 核心原则

行为保持型简化是在不改变输入、输出、副作用、错误、日志、事件或持久化结果的前提下降低复杂度。

## 适用场景

- 用户要求简化、清理、优化或重构代码，且没有要求改变行为。
- 用户要求提升现有代码可维护性。
- 已确认计划属于行为保持型改动。

当用户要求新增功能、改变业务规则或修复行为时，不使用本技能作为主要流程。

## 必须保持的不变量

必须保持：

- 公开函数、模块和 API 的输入输出。
- 返回值和抛错行为。
- 副作用、日志、事件、持久化和外部调用。
- 业务规则和权限行为。
- 现有用户可见流程。

## 简化优先级

优先：

- 删除无意义的间接层。
- 拉平线性控制流。
- 简化条件分支。
- 在命名掩盖意图时改善命名。
- 保持状态显式、局部。

避免：

- 为简单逻辑引入策略 / 工厂 / 注册表抽象。
- 大范围格式 churn。
- 顺手修复无关 bug。
- 添加当前任务不需要的未来灵活性。

## 验证

修改代码前，确认已有测试或手动等价性检查。修改后，按项目规则运行最接近的可用验证。

如果无法证明行为等价，停止并报告风险，不要扩大重构范围。

## 硬边界

- 除非用户明确批准，不改变可观察行为。
- 不新增功能或业务规则。
- 不以「可读性更好」为理由跳过验证。
